# 系统框图模块重做 · 设计说明

- 日期：2026-09-18
- 范围：`assets/js/modules/blockdiag.js` 全量重做，新增 `assets/js/lib/blocksolve.js`，少量 `index.html` / `assets/css/style.css` 适配
- 目标：符号体系对齐教材（方框 / 求和点 / 分支点）、交互从"能用"提升到"顺手"、布局与视觉重排到"结构清晰、观感精致"
- 非目标：不引入第三方图形/布局库（本站零依赖约定）；不做非线性环节（饱和、死区、间隙）；不做时域闭环仿真

---

## 1. 现状与问题

| 类别 | 具体问题 |
| --- | --- |
| 符号 | 只有"方框"，求和与分支靠 `R` / `Y` 徽标模拟，与教材框图不一致 |
| 画布 | SVG `viewBox` 固定 `0 0 960 460`，块坐标硬夹在框内，**无平移/缩放**；窄屏等比缩到约 0.36×，端口半径 5px 实际约 2px，移动端无法拖线 |
| 连线 | 拖拽仅一条虚线，目标端口无吸附反馈，落点无效静默失败 |
| 编辑 | 传函只能回左栏输入框改；块名不可改；长表达式截断为 `…` 且无 tooltip |
| 删除/纠错 | 只能点线上小 `✕` 徽标；无撤销/重做；清空无确认 |
| 布局 | 左栏混"工具+列表+长提示"，右栏混"画布+T(s)+指标"，阶跃响应另置底部折叠面板；信息层级是平的 |

**就地改造的理由**：模块只自注册、不被其它模块依赖，改动风险可控；而教科书符号是教学工具的核心价值，属于必须解决的局限。

## 2. 架构

拆成两层，求解层与 DOM 解耦：

```
assets/js/lib/blocksolve.js   ← 新增：纯函数，无 DOM，可在 Node 中测试
assets/js/modules/blockdiag.js ← 重做：状态 + 渲染 + 交互 + 检查器
```

`blocksolve.js` 暴露 `window.BLKSOLVE`：

| 导出 | 作用 |
| --- | --- |
| `polyMul / polyAdd / pTrim / polyDivMod / polyGCD / freduce` | 多项式与有理函数工具（从原 blockdiag.js 迁出） |
| `parseBlockTF(str)` | 解析块传函 → `{ ok:true, n, d }`（已约分、分母首项归一）或 `{ ok:false, reason }`。`reason` 取值：`'无法解析'` / `'分母首项为 0'` / `'非真分式（分子阶次 > 分母阶次）'`。**判定全部收敛到此函数**，块层只负责把 `ok:false` 映射为 `err = true` 并把 `reason` 透给检查器显示 |
| `solveTransfer(nodes, edges)` | 信号流图 → `{ ok, frac, note }`，含能控规范型、代数回路求解、零极点对消 |
| `deriveReadout(frac)` | 由结果派生"阶次 / 闭环极点 / 稳定性 / ωₙ / ζ"（只依赖 `frac`，不依赖拓扑） |

`blockdiag.js` 只负责：状态、SVG 渲染、指针交互、检查器 UI。**求解内核数学逻辑保持不变**（仅搬家 + 去掉 `void frac` 之类的死代码）。

## 3. 数据模型

```js
node = {
  id,                    // 自增整数
  kind: 'box' | 'sum' | 'branch',
  name,                  // 'G₁' / 'Σ₁' / 'n₁'，可改
  str,                   // 仅 box 使用；sum/branch 恒为 '1'
  f,                     // { n, d }，已约分；不合法时为 null
  err,                   // 仅 box：parseBlockTF 返回 ok:false
  errNote,               // 仅 box：错误原因，直接来自 parseBlockTF.reason
  x, y,                  // 世界坐标（节点左上角；sum/branch 为圆心外接框左上角）
  src                    // 仅 sum：是否注入单位输入 R（取代原 mark='in'）
}

edge = { from, to, sign: +1 | -1 }   // sign 为入边符号，−1 显示在 Σ 圈上
```

规则：

1. `sum` / `branch` 的传函恒为 `1`，因此**现有 `u_i = Σ(±y_j)` 线性方程组直接支持**，求解内核无需改动。
2. **输出由显式的"输出端子"指定**：节点上的 `out: true` 表示从该节点引出输出 `Y(s)`；可标记多个，**多个输出按"求和"合并**（沿用现有实现的既有语义，`§10` 的并联用例依赖此约定）。未标记任何输出时，回退为"没有出边的节点（汇点）之和"。
   > 为什么必须有显式端子：纯反馈拓扑（`Σ ⇄ G`）里每个节点都有出边，按"汇点"推断会得到 **T=0**，与教材结果 10/(s+11) 不符；教材框图本身也是用一个显式的 `Y(s)` 箭头标出输出。
   - 视觉上不再是原来那个小方徽标，而是从节点右侧引出的**短箭头 + `Y(s)` 标签**（`§6`）。
   - 输入侧同理：`sum` 的 `src: true` 渲染为带 `R(s)` 标签的**输入端子**。
3. 输入激励：用户把某个 `sum` 标为"接 R"（`src = true`）；没有标记时沿用现有回退（无入边的节点注入单位输入，仍无则首节点）。
4. `branch` 为显式类型；同时**保持宽容**：任何节点出度 ≥ 2 都在视觉上渲染引出点圆点，不必强制用户先建分支点。
5. **`from === to` 的自环是"交互层规则"，不是数据层约束**：UI 不允许把端口连回同一个节点；但 `solveTransfer` 对输入图不做 DAG 假设、也不特判自环，按一般有向图参与线性方程组求解（这样求解层可被单测直接驱动，不必依赖 UI 拦截）。
6. 同一 `from→to` 只允许一条边（重复连线改为更新符号并提示）。
7. **编辑入口唯一化**：左栏元件列表改为只读展示（图标 + 表达式 + 选中态），不再嵌输入框；改表达式只在两处——双击画布上的块，或在右栏检查器输入。避免"列表 / 检查器 / 画布"三处不同步。

## 4. 几何与视图

- 方框：`W=120, H=46`；入端口 = 左边中点，出端口 = 右边中点。
- 求和圈：半径 `20`，出端口在右；入端口候选方位为**左 / 上 / 下**三槽，按落点角度自动分配最近的空槽，三槽占满则复用左槽（允许轻微重叠）。
- 分支点：半径 `5` 实心，端口在圆心，四向可接。
- 视图变换：世界坐标 → 屏幕用 `<g transform="translate(tx,ty) scale(s)">`，`viewBox` 跟随容器像素尺寸。平移/缩放只改 `transform`，网格用 `pattern` 反向缩放保持屏幕密度稳定。
- 工作区**不设边界**，内容自适应外扩；`适应窗口` 按内容包围盒计算 `s/tx/ty`。
- 命中检测统一走 `svg.getScreenCTM().inverse()`，所有容差以**屏幕像素**定义（如端口 `14px`），从根本上解决缩放下点不中的问题。
- 自动布局：按拓扑深度分列、同层竖直均分（用于"载入示例"与"整理布局"按钮）。
- **渲染分层（性能前提）**：`<g id="g-static">`（网格 / 块 / 连线）只在结构或选中态变化时重建；`<g id="g-overlay">`（拖拽预览、吸附环、框选矩形、对齐辅助线）只改属性，不重建 innerHTML。避免 `pointermove` 期间整棵 SVG 重排——这是"手感是否顺"的关键。
- 拖拽块时只写被拖节点的 `transform`，不触发全图重绘；松手后统一 `update()` 并压入撤销栈。

## 5. 交互规格

工具：**只有 `选择 / 平移` 两态**（画布左上角常驻），`空格` 临时切平移。连线不需要独立工具——在"选择"态下直接从端口拖出即可（触屏上长按端口即进入连线），因此去掉原设计里的"连线"工具，减少一个需要理解的状态。

| 手势 | 行为 |
| --- | --- |
| 点空白 | 取消选择 |
| 拖空白（选择工具） | 框选；`Shift` 加选 |
| 拖空白（平移工具 / 空格 / 中键） | 平移视图 |
| 点节点 | 选中；`Shift` 加选；拖节点移动（多选整组移动） |
| 拖端口 | 连线；目标端口出现**吸附环 + 落点预览**，无效目标转红；空白处松手弹出"创建求和点 / 分支点 / 方框" |
| 双击方框 | 就地编辑传函（浮层输入，`Enter` 提交 / `Esc` 取消） |
| 双击名称 | 就地改名 |
| 悬停节点 | 显示完整表达式 tooltip（长表达式不再只说 `…`） |
| 右键节点 / 连线 | 上下文菜单：复制、删除、断开全部连线、切换符号（±）、设为输入 R(s) / 设为输出 Y(s)（均可取消） |

## 7. 移动端适配（重点）

移动端不是"缩小版桌面"，是**独立的交互与布局形态**。现状最大的问题就在这里：固定 `viewBox` 在手机上等比缩到约 0.36×，端口只剩约 2px，等于完全不可用。

### 7.1 布局

沿用站点既有的单列堆叠约定（`@media (max-width: 900px)` 已把 `.layout` 折成 `1fr`），不新造抽屉体系：

| 宽度 | 形态 |
| --- | --- |
| `> 1180px` | 三栏：左 240 / 中 `1fr` / 右 300 |
| `901–1180px` | 两栏：左 220 / 中 `1fr`；右栏降到画布下方，横向选项卡 |
| `<= 900px` | 单列堆叠：**① 画布**（`height: clamp(300px, 52dvh, 440px)`，`100dvh` 优先并保留 `100vh` 回退，与站点侧栏一致）→ ② 检查器 → ③ 元件列表。工具条与缩放控件**贴画布内部**（绝对定位），不额外占纵向空间 |

### 7.2 触控交互（与鼠标并行存在，不互相阻塞）

| 手势 | 行为 |
| --- | --- |
| 单指拖节点 | 移动节点 |
| 单指拖空白 | 平移画布（触屏不做框选，避免与平移打架） |
| 双指捏合 | 以两指中点为锚点缩放（复用 `FX.Plot` 里已验证的 `_pointers` + `_pinch` 模式，与站内其它图一致） |
| 手指从端口拖出 | 连线。**端口命中优先于节点**，命中区外扩到 ≥ 44px 触控直径（视觉半径不变），解决"点不中" |
| 长按（450ms）节点 / 连线 | 上下文菜单（取代右键） |
| 双击节点 | 仅桌面启用（触屏改用长按菜单里的"编辑表达式"） |

### 7.3 无键盘时的可达性

移动端没有键盘，因此以下能力**必须有可见按钮**（触控尺寸 ≥ 40×40）：撤销、重做、删除选中、适应窗口、缩放 ±、分享、载入示例、清空。
桌面保留快捷键（`§5`），移动端一律通过按钮走同一套命令函数。

### 7.4 移动端专属细节

- 画布 `touch-action: none`，防止拖动节点时页面跟着滚（站点其它画布同此约定）。
- 点阵网格在 `<= 900px` 时改用更大间距（避免小屏上的视觉噪点）。
- 线宽与描边在触屏下 +0.2px，抵偿高分屏的视觉变细。
- 触屏上不显示 hover tooltip（无悬停态）；完整表达式改由**选中时在检查器标题下方展示**。
- 检查器输入框在 `<= 900px` 时 `font-size: 16px`，防 iOS 聚焦自动放大（站点既有做法）。
- 移动端默认缩放到 `适应窗口`，确保载入示例后整图可见。

### 7.5 验收（真机/模拟窄屏）

- 375×667（iPhone SE 级）与 390×844 下：不加缩放即可看见完整示例框图；单指拖节点不触发页面滚动；从端口拖线能稳定命中；双指捏合缩放以中点为锚不漂移。
- 380px 宽下三块按钮组不换行溢出，画布不横向溢出产生滚动条。

## 8. 错误处理

| 情况 | 处理 |
| --- | --- |
| 块表达式解析失败 | 块描边变红 + ⚠ 徽标；检查器显示示例；参与求解的节点自动跳过（沿用现有 `!n.err && n.f` 过滤），并在结果区提示"有 N 个块表达式无效" |
| 分母首项为 0 / 非真分式 | 允许提交（不丢用户输入），但块标记为 `err = true`、`errNote = parseBlockTF.reason`：描边变红 + ⚠ + 检查器内联显示该 `reason`；该块不参与求解 |
| 代数环无解（`matInv` 返回 null） | 结果区明确提示"存在无延迟代数环，无法求解"，而非静默显示空 |
| 结果出现 NaN/Inf | 指标显示 `—` 并附一行说明 |
| 撤销栈为空 | 按钮置灰 |

## 9. 迁移与兼容

- 旧模块没有写入 hash 分享；本次补上**结构化分享**：`#blk=<version>.<base64(JSON)>`，编码 `{ nodes, edges, view }`，刷新可完整还原；编码失败时降级为不写 hash 并保持功能可用。此条属"顺带补能力"，排在最后一步；若实现阶段发现预算紧张，可整条裁掉而不影响前四项。
- "载入示例"换成三套教科书结构：① 一阶单位负反馈 ② 二阶带前置滤波 ③ 串并联对比。
- 资源版本号：`index.html` 中新增脚本与改动脚本的 `?v=5.9` → `?v=6.0`，侧栏版本标签 `v3.2` → `v3.3`。
- `dispose()` 必须断开 `ResizeObserver`、清空未触发的防抖定时器、移除 `window` 级监听。

## 10. 验证

1. `node --check` 覆盖全部改动文件。
2. `node tests/lib.test.mjs` 保持全绿（本次不改动 `util/mathdsp/transforms`）。
3. 新增 `tests/blocksolve.test.mjs`。每个用例都写明拓扑，避免歧义：
   - **单位负反馈（教材拓扑，无自环）**：`sum`（标记接 R）→ `G=10/(s+1)`，`G` 的输出以 `sign=−1` 回到同一个 `sum` → `10/(s+11)`（`Y/R = G/(1+G)`）
   - **串联**：`A=1/(s+1) → B=1/(s+2)`，`A` 接 R，`B` 无出边（即输出）→ `1/(s²+3s+2)`
   - **并联**：`A=1/(s+1)`、`B=1/(s+2)` 由同一个 `sum`（标记接 R）分别驱动，两者均无出边 → 总输出为两汇点之和 `(2s+3)/(s²+3s+2)`
   - **求和点/分支点不改变结果**：在串联链中间插入一个 `branch`、并在末端接一个 `sum`，结果与"串联"用例一致
   - **零极点对消**（断言 `parseBlockTF`）：`(s+1)/((s+1)*(s+2))` → `{ n:[1], d:[1,2] }`
   - **非法输入不抛异常**：空串、`"1/0"`、`"1/(0*s+1)"`、`"1/s/s"` 均返回 `null` / `{ ok:false, note }`
   - **代数环无解**：构造无延迟代数环 → `{ ok:false }` 且 `note` 非空
4. `node tests/blk-dom-contract.test.mjs`（静态契约）：模块引用的每个 id / data-* 都能在自身模板里找到，且没有只写不读的死属性。这类"选择器打错"是 SVG 编辑器最容易在某个分支才炸的缺陷。
5. `node tests/blk-interaction.test.mjs`（交互逻辑，无浏览器）：用极简 DOM 桩把模块真正实例化，再合成 pointer 事件跑完整链路并断言可观测产出——初始化与示例载入、新符号渲染（Σ / R(s) / Y(s) / 虚线反馈 / 圈上 ±）、拖动与对齐吸附、撤销重做、端口拖线到空白处弹菜单并**自动接上来源**、结果页签切换、无按键移动零改动、触屏长按菜单、拖动取消长按、双指捏合缩放、删除与清空、分享链接还原。
   > 边界说明：该套件验证的是**状态机与算法**，桩会假造 `getBoundingClientRect` / `getContext` / 元素查询，因此不能替代真机上的视觉与触感验收。
