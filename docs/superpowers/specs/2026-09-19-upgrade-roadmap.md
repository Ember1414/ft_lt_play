- 日期：2026-09-19

## 2. 逐模块清单

### 2.1 `system` 系统分析（优先级 1）

- **现有能力**：Bode（对数轴）、奈奎斯特（含 (−1,0) 标注 + **简化**判稳提示 `system.js:450-452`）、根轨迹（分支追踪/渐近线/分离点/虚轴穿越 + K 滑杆，`:277 getRootLocus`、`:455 drawRoot`）、阶跃/脉冲响应、PM/GM/带宽/ζ/ωₙ（`:604`）、劳斯表（`:724 routhCompute`）、特征方程与自由响应（`:798`）
- **缺口（章节级）**：
  1. **状态空间分析整章缺失**：可控/可观标准型、能控能观判据、状态反馈与极点配置、状态观测器
  2. **离散系统分析整章缺失**：`z` 域系统函数、离散稳定判据、离散响应
  3. **奈奎斯特完整判据**：现仅「开环稳定」简化式，缺 Z=N+P 与包围计数
  4. **稳态误差与系统型别**：缺 Kp/Kv/Ka、型别 0/1/2 与误差系数表
  5. **校正装置设计**：仅 `system.js:131-132` 的「超前/滞后」**预设输入**，缺频域法设计（超前/滞后/PD/PID，参数按 φm/ωc 反算）
- **建议升级点**：① 状态空间页签（能控型实现可直接复用 `blocksolve.js:124-135` 已有的 A/B/C/d 构造，导出即可）② 离散系统页签（复用 `BLKSOLVE.solveSampled/deriveZReadout`）③ 奈奎斯特完整判据 + 包围数动画 ④ 稳态误差系数表 ⑤ 校正设计向导（先给超前/滞后）
- **触屏**：FX.Plot 已带捏合（`plots.js:146`），缺长按菜单与 `dvh`
- **成本**：**L**（新引擎 + 多画布，建议拆成 3 个子批次：状态空间 / 离散 / 校正）

### 2.2 `zt` Z 变换（优先级 2）

- **现有能力**：`H(z)` 输入（正幂、因式展开、非真分式给警告）、z 平面零极点点击加/拖/双击删/共轭成对（`zt.js:281-353`）、单位圆稳定判据与最大极点模（`:169`）、`H(e^{jω})` 幅相（`:362`）、`h(n)` 解析式（`:191` `TR.invZ`）、差分方程递推响应（`:388 simulate`）
- **缺口（章节级）**：
  1. **差分方程直接输入/求解**（现仅由 H(z) 反推冲激响应）
  2. **多 ROC 选择与可视化**：现仅因果单支
  3. **双边 Z 变换**与 ROC 分支（左边/双边序列）
  4. **Jury 判据**等离散稳定判据（现仅「极点模 <1」）
  5. **s↔z 映射交互**（脉冲响应不变 / ZOH / 双线性），现仅 `explore.js:666` 的冲激不变数值法
- **建议升级点**：① 差分方程输入 → 递推 + 解析解 ② ROC 分支切换（点在 ROC 内/外联动收敛性）③ Jury 判据表 ④ s↔z 三种映射对比页签（`BLKSOLVE.sToZ/zohDiscretize` 已就绪，可加 Tustin）
- **触屏**：z 平面已用 pointer，但**缩放只有 wheel（`zt.js:328`）→ 无捏合**；无双击删除的触屏保障、无长按菜单
- **成本**：**M**

### 2.3 `pid` PID（优先级 3，投入产出比最高）

- **现有能力**：5 个**写死**对象（`pid.js:12-17`）、Kp/Ki/Kd 滑杆 + 整定套路（`:90-101`）、闭环阶跃响应与 σ%/tr/ts/ess/y∞（`:170`、`:217`）、闭环极点手写静态画布（`:140`）、T(s) 与稳定性
- **缺口（章节级）**：
  1. **抗积分饱和（anti-windup）**：反算/限幅/条件积分
  2. **微分改进**：微分先行、不完全微分（D 加低通）
  3. **数字 PID**：位置式/增量式、采样周期、离散闭环（可直接接 `BLKSOLVE`）
  4. **整定方法**：Ziegler–Nichols 临界比例度/衰减曲线、Cohen–Coon、CHR
  5. **性能指标**：ISE/IAE/ITAE 与最优参数搜索
  6. **可编辑对象**：现在只能从 5 个里选，无法输入自己的 G(s)
- **建议升级点**：① 被控对象改为任意 `G(s)` 输入（复用 `FX_LIB.parseTFFields`）② 抗饱和/微分滤波开关（滑杆即得）③ 整定方法一键给参数 ④ ISE/IAE/ITAE 指标栏 ⑤ 数字 PID 页签（复用 `BLKSOLVE.solveSampled`）⑥ 极点图换成批次 1 的共享复平面画布
- **触屏**：极点图**完全无交互**；range/btn 靠全局 CSS 兜底（`style.css:645-648`）；无长按菜单
- **成本**：**S–M**（多为算法 + 滑杆）

### 2.4 `laplace` 拉普拉斯（优先级 4）

- **现有能力**：预设/手动 H(s)（因式、复极点、重极点）、s 平面零极点编辑 + ROC + 稳定性、留数法反变换解析解 + 数值叠加（`laplace.js:372`、`:469`）、迷你阶跃预览、分享链接
- **缺口（章节级）**：
  1. **变换性质交互验证**：时移/频移/尺度/卷积/初值定理/终值定理
  2. **双边拉普拉斯与多 ROC**（左边/双边信号）
  3. **微分方程含初始条件的 s 域求解**：零输入/零状态分解
  4. **s 平面几何法**（|H(s)| 曲面/向量法求频响）
- **建议升级点**：① 性质验证器（改动输入 → 两侧同时重绘）② ROC 分支选择 ③ 微分方程输入 → 零输入/零状态 + 全解 ④ s 平面接入共享复平面画布
- **触屏**：**s 平面完全不可用**（`laplace.js:550/561/568` 全是 mouse 事件）→ 批次 1 的首要受益者
- **成本**：**M**

### 2.5 `ft` 傅里叶变换（优先级 5）

- **现有能力**：时↔频联动（`ft.js:79`，FFT 谱）、卷积定理动画 + 频域验证（`:209`、`:318`）、采样定理/混叠/三种重建（`:433`、`:491`）
- **缺口**：变换性质（时移/频移/尺度/对偶/卷积）的动态验证、Parseval 能量定理、任意 `x(t)` 的数值 FT 与逆变换、周期信号与级数衔接、调制与频分复用
- **建议升级点**：① 性质验证器（复用 `ft` 现有时↔频联动框架）② Parseval 能量对比（时域积分 vs 频域积分）③ 任意信号输入（`FX_LIB.parseTimeExpr`）④ 调制演示
- **触屏**：FX.Plot 可捏合；缺长按菜单与 `dvh`
- **成本**：**M**

### 2.6 `fs` 傅里叶级数（优先级 6）

- **现有能力**：DFT 相量链动画（`fs.js:248`、`:261`、`:336`）、谐波幅度谱（`:458`）、方波部分和 + Gibbs RMS（`:416`、`:482`）、3D 瀑布自写投影（`:503`、`:513`）
- **缺口**：三角/指数型系数 `aₙ/bₙ/cₙ` 的**解析公式**计算、奇偶对称性化简、**任意周期信号（解析/分段）输入**（现仅 7 个预设 + 手绘，`fs.js:14-15`）、Dirichlet 条件、复数频谱与相位谱、级数↔变换极限
- **建议升级点**：① 解析/分段输入 + 系数解析式（复用 `DSP.dftPhasors` 做数值对照）② 对称性自动判定与化简提示 ③ 相位谱页签
- **触屏**：有捏合（`:307`）与 3D 捏合（`:616`）；缺长按菜单、`dvh`、固定 `height` 画布
- **成本**：**M**

### 2.7 `explore` 求解探索（优先级 7）

- **现有能力**：表达式自动识别时域/传函并绘图（`:187`、`:252`）、**符号变换 6 模式**（含 `s→z` 冲激不变 `:666`，带数值验证 `:639`）、手绘→DFT、语音输入（`:460`）、历史/分享
- **缺口**：卷积/相关求解、微分方程零输入+零状态求解、**离散化方法可选**（现仅冲激不变）、初值/终值定理验证、部分分式步骤可视化
- **建议升级点**：① 局部与 `ft`/`la`/`zt` 重叠，宜把它定位成「一个入口跑多种求解」：补卷积/相关与微分方程 ② 离散化方法下拉（冲激不变/ZOH/双线性，前三者内核已有或可加）③ 静态极点图接入共享画布
- **触屏**：符号键盘对触屏友好（`:65-81`）；无长按菜单、`dvh`
- **成本**：**S**（以整合为主）

### 2.8 `derive` 推导（优先级 8）

- **现有能力**：静态性质表 + 变换对（含 ROC，`:7-74`）、5 个逐步推导（`:76-145`）、自定义 `f(t)` 逐步推导 + 数值验证（`:210`、`:286`）、公式字号缩放（`:477-486`）
- **缺口**：部分分式/反变换推导、卷积定理与初值终值定理推导、性质对自定义信号的交互验证、傅里叶级数系数通用推导、对偶性演示
- **建议升级点**：① 推导引擎扩到 `F(s)`/`X(z)` 反变换步骤 ② 性质验证（与 `ft`/`la` 共用同一个验证器）③ 与 `fs` 衔接系数推导
- **触屏**：导航与表格已横向滚动（`style.css:661-666`）；无画布需求，无需大改
- **成本**：**S**

## 4. 每个批次的执行与验收（沿用 `blk` 的做法）

1. 先给**分段设计**（数据模型 / 数学 / 交互 / 移动端 / 测试）并逐段确认；
2. 落设计文档到 `docs/superpowers/specs/`，用户审阅后再实现；
3. **先测后码**：新增/扩充 `tests/*.test.mjs`，纯函数内核与 DOM 桩交互测试分层；
4. 验证一律走**代码层**（`node --check` + 全部测试脚本），**不跑浏览器**；真机视觉项单列人工验收清单；
5. 每个模块收口时同步：`index.html` 版本号、`.blk`/模块自身的响应式段、分享链接兼容。
