# M14 验收单 · 奈奎斯特「刚越过临界增益」档位的圈数（临界邻域加密覆盖全部近临界段）

> 依据：M11 验收单 §五 第 1 项残留——`G=K/(s(s+1)(s+2))` 在 `K∈(6, ~6.05)` 时 `Z` 报 **1**（真值 2），
> 「若要彻底消除，需要自适应细分（按弦偏差动态加密）而非固定密度」。
> 交付 = 可运行版本 + 本验收单。版本 **2.9.0**。

## 一、根因（本轮实测改写了 M11 的推测）

M11 以为残留来自「固定密度不够」，并推测应改「按弦偏差的自适应细分」。本轮先做了**密度扫描实测**
（`seg = 125 / 500 / 2000 / 8000 / 32000`，代表用例各档的 `N` 与辐角和），得到两个反直觉事实：

1. **粗采样可能「稳定地漏看」局部几何**：`K=6.01` 在 125/500/2000 三档都给出 `N=0`，且相邻档辐角和之差
   仅 ~1e-16（机器精度）。也就是说**「结果在相邻档之间不变」并不能证明答案正确**——
   多边形对自身是精确的，它只是没看到该看的穿越。**因此不能用「结果收敛就停」替代固定密度。**
2. **残留的真正原因是加密只覆盖了「一个」近临界段**：该族刚越过临界增益时，曲线在 `ω=±√2` 有**两个对称穿越**
   （−1.0017 深处），M11 只加密了距离最小的**单个**轴段 → 只补回约半圈 → `N` 从 0 只到 1（Z=1）。

## 三、功能验收清单（真值一律取 Routh–Hurwitz 闭式）

- [x] **族一 `G=K/(s+1)³`**（Routh 首列 `[1,3,(8−K)/3,1+K]`）：`K=8.01`（刚越过 0.125%）由 **Z=1 → Z=2**；
      `K=2/4/7/7.9/7.99` 仍 `Z=0`；`K=8.05…20` 全 `Z=2`；`K=8` **临界**（`Z=0`、`onCritical=true`）
- [x] **族二 `G=K/(s(s+1)(s+2))`**（Routh 首列 `[1,3,(6−K)/3,K]`，含原点极点需 indent）：`K=6.01/6.02/6.05` 由 **Z=1 → Z=2**；
      `K=4/5/5.9/5.99` 仍 `Z=0`；`K=6` **临界**（`Z=0`）；`K=6.1…8` 全 `Z=2`
- [x] **族三 `G=K/(s+1)⁴`**（临界增益 4）：`K=3.9 → Z=0`、`K=4`（临界）→ `Z=0`、`K=4.1/5/6/8 → Z=2`
- [x] 扫描全部用例（46 个档位 × 3 族）与 Routh 闭式真值**逐项一致**；仅两处「不一致」出现在**精确临界增益**
      （`K=8`、`K=6`）——那是测试脚本的 Routh 辅助函数未处理「零行」所致，`nyquistFull` 返回 `Z=0` 才是正确值
      （审计 #12 的 `K=8 / K=6` 断言即为 `Z=0 && onCritical`）
- [x] **回归网不受影响**：16 组奈奎斯特对拍用例的 `P/N/Z/stable/onCritical` 与 v1 逐字段一致（`parity` 77/77 + 37/37）
- [x] 审计 #12 由 8 条扩为 **11 条**闭式断言（新增 `K=8.01`、`K=6.01`、`K=6.02` 三个「刚越过临界」档位）
- [x] **浏览器实测**（零业务 console error）：`系统分析` 设 `L(s)=1/(s^3+3s^2+2s)` →
      K=5.9「闭环 稳定（Z=0）」→ **K=6.01「闭环 不稳定（Z=2）」**（修复前 Z=1）→ K=6「闭环 临界（Z=0）」→
      **K=6.02「闭环 不稳定（Z=2）」**
- [x] 性能：`nyquistFull` 单次 0.87 ms（无虚轴极点）/ 1.45 ms（含原点极点）——与 M11 同量级（挑段加密的额外开销 ≈ 5–18%）

## 五、说明与遗留

1. **M11 §五 残留已闭合**：三族扫描中再无「真值 2 却报 Z≤1」的档位；此前 0.9% 的窗口（K∈(6, 6.05)）不再存在。
2. **本轮的负结论也有价值**：已在代码注释与本节写明「相邻档结果一致 ⇒ 答案正确」是**伪判据**，
   防止后人以「收敛就停」替换几何挑段（本轮实测数据即为此结论的证据）。
3. 挑段上限 `NYQ_REFINE_MAX=4` 与门限 `NYQ_REFINE_FACTOR=4` 是经验值：4 段足以覆盖
   「正负频率对称穿越」（2 段）、多次穿越（3+ 段）等常见形态；若遇到需要更多段才收敛的极端传函，
   可调这两个常量（**改动后必须重跑 `parity` + `audit` #12**，见 README「内核约定」）。
4. 加密只发生在**虚轴直线段**；落在 indent 弧段或位于首/末采样点的临界邻域仍不加密（保持 v1 行为）。
5. 其余已知边界见《M12 验收单》§五（实例回读有效参数需跨 13 工具改动）与《M13 验收单》§五（CI 不跑浏览器）。
