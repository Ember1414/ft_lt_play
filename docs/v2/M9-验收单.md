# M9 验收单 · 剧场剧本编辑器与分享（自建剧本库）

> 依据：M5 验收单 §五 第 3 项遗留——「剧场脚本编辑（自建剧本）与分享」。
> 交付 = 可运行版本 + 本验收单。版本 **2.4.0**。

## 一、交付范围

| 项 | 内容 |
|---|---|
| 剧本库 | `state/theater.ts`：内置 `SCRIPTS`（5 部，**只读**）+ 自建（`localStorage['flt2:theater:scripts']`）；`getAllScripts()` 合并返回，`getScript()` 内置优先 |
| 存储降级 | 启动探测 localStorage 不可用 → 自建剧本退化为**内存态**（页面提示「存储不可用…刷新后丢失」，功能不阻塞） |
| 编辑器 | `pages/Theater.tsx`：名称 / 简介 + 每步「工具下拉（13 工具）· 停留时长（`NumField` 0.3–20s）· 旁白字幕 · 参数 JSON（`textarea.c-area`）」+ 上移 / 下移 / 删除 / 添加一步（上限 40 步） |
| 导出 | 每部剧本可「导出剧本」(`.json`，含 `kind:'fltp-theater'` 外壳) 与「复制剧本分享码」(`TS1.<b64u>.<fnv1a>`，上限 16000 字符) |
| 导入 | 「导入剧本」单输入框：接受 `TS1.…` 分享码，也接受 `.json` 文本（`importScriptText`）；同名自建剧本按 id 覆盖并在 toast 中说明 |
| 内置保护 | 内置剧本的「编辑」→ 自动生成**自建副本**（新 `u-` id，名称加「（自建副本）」），内置内容不被改写 |
| 错误提示 | 解码失败逐类给因：格式不对 / 校验失败 / base64 不可解 / JSON 解析失败 / kind 不匹配 / 结构非法 |

## 二、功能验收清单

- [x] 列表渲染 `getAllScripts()`；内置标「内置」、自建标「自建」；顶部计数「共 N 部剧本（内置 x 部 / 自建 y 部）」
- [x] 「+ 新建剧本」进入编辑器；保存前逐项校验（名称非空、工具存在、参数为 JSON 对象），失败给出行号级原因
- [x] 保存后列表即时出现自建剧本卡片（实测：5 部 → 6 部，自建 0 → 1）
- [x] ▶ 播放自建剧本：逐步切换工具 + 旁白条推进至结尾自动结束（实测走完「第 2 / 2 步 · 已结束」）
- [x] 「复制剧本分享码」生成 `TS1.…`；剪贴板不可用时降级为**可手动复制**的提示框（本机实测触发该降级）
- [x] 「导入剧本」：粘贴 `TS1.…` → toast「已导入剧本「短剧本B」（1 节）」、计数 → 7（自建 2）、新卡片带「自建 · 1 节」徽标
- [x] 「导入剧本」失败路径：输入 `abc` → toast「导入失败：既不是 TS1.… 分享码，也不是合法 JSON」
- [x] 「编辑」自建剧本 → 编辑器字段回填正确（名称、两步工具下拉、参数 JSON）→「取消」返回列表
- [x] 空名称 / 空步骤 / 非法 JSON 均拒绝保存并提示
- [x] 自建剧本可「删除」，删除后列表与计数即时更新（断言层验证）

## 五、说明与遗留

1. **自建剧本随实验一起备份** → **M10 已完成**：备份包新增 `theaterScripts` 字段，「导出全部数据 / 导入备份」
   与「恢复出厂设置」均已覆盖剧本库（见《M10 验收单》）。当前 `设置 · 备份与恢复` 导出的是「全部实验 + 自建剧本」；
   主题 / 动效偏好与学习路径进度仍由各自入口管理。
2. 分享码为 base64url + FNV-1a 校验，**非加密**：仅防传输损坏，不防伪造——与实验 `PX1` / 内容包 `PK1` 同一强度取向。
3. 导入时以 `u-` 前缀 id 覆盖同名自建剧本；内置 id（`t-`）一律重分配新 id，因此分享内置剧本副本不会污染内置内容。
4. 「26 项剧本编解码断言」原为临时脚本，**已并入 CI → `scripts/uidata.mjs`**（`npm run uidata` 的第 ① 组，
   现有 26 条；见《M13 验收单》）。该脚本与 `parity.mjs` / `audit.mjs` 同一手法（esbuild 打包 +
   `localStorage` 桩），定位为**内核之外**的 UI 数据层门；JSX 渲染与交互仍由浏览器走查负责。
5. 剧场的参数插值（M5）对自建剧本同样生效（同工具连续步之间仅对连续型数值参数插值）。
