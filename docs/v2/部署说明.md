# v2 部署说明（Cloudflare Pages + CI）

> 目标：v2 为**纯静态 local-first 应用**（无后端、无外部请求），构建产物 `v2/dist` 可直接托管到任意静态平台；
> `base: './'`（相对路径）→ 可部署到根路径或任意子路径。本仓 CI 在 `push main` 时校验 v1 与 v2，并按需发布 Pages。

## 1. 构建与产物

```bash
cd v2
npm ci          # 锁定依赖
npm run check   # TS strict 类型检查（发布前闸门）
npm run parity  # v1↔v2 内核对拍 + 闭式真值（红线）
npm run audit   # 内核语义 / 审计断言（§四 空洞 + #12/#14/#9）
npm run uidata  # UI 数据层断言（剧本库 / 备份包 / 参数表 / 指标对照 / 坐标图刻度与缩放规则）
npm run perf    # 主线程重算开销巡检（灾难级预算 + 基线表）
npm run build   # → v2/dist（含 public/_headers 复制）
npm run preview # 本地预览 http://localhost:5200
```

产物体积基线（2.13.0 实测）：入口 chunk JS **177.3 KB（gzip 74.2 KB）**；KaTeX 262.5 KB + CSS 28.5 KB **按需加载**；13 个工具各自独立分片 9–24 KB；dist ≈ 1.80 MB。

## 2. Cloudflare Pages 发布

**方式 A：CI 自动发布**（推荐）
1. 在仓库 Settings → Secrets and variables → Actions 添加：
   - `CLOUDFLARE_API_TOKEN`：Cloudflare 控制台 → My Profile → API Tokens → 创建“Edit Cloudflare Workers”模板或自定义（权限至少 `Account → Cloudflare Pages → Edit`）
   - `CLOUDFLARE_ACCOUNT_ID`：控制台右侧 Account ID
2. `push` 到 `main`（且改动含 `v2/**`）时 `.github/workflows/deploy-v2.yml` 会自动构建并发布到 Pages 项目 `ft-lt-play-v2`。
3. 未配置密钥时该 workflow **跳过部署步骤并打印提示**，不会让 CI 变红。

**方式 B：本地手动发布**
```bash
cd v2 && npm run build
npx wrangler pages deploy dist --project-name=ft-lt-play-v2
```

**方式 C：GitHub Pages（备选）**：把 `v2/dist` 作为 Pages 产物上传即可（相对 base 已适配子路径）。若采用此方式，请勿同时启用方式 A，以免出现两个入口。

## 3. 缓存与安全头（`v2/public/_headers`）

构建时 Vite 会把 `v2/public/` 原样复制进 `dist/`，因此 `dist/_headers` 随产物一起发布：

| 路径 | 策略 | 原因 |
|---|---|---|
| `/assets/*` | `max-age=31536000, immutable` | 文件名含内容哈希，可永久缓存 |
| `/index.html` | `no-cache` | 升级后立即拿到新入口 |
| `/*` | CSP 等安全头 | 见下 |

CSP 要点（与 v1 的差异：v2 的 KaTeX 是**本地打包**，不再需要放行任何 CDN）：

```
default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline';
font-src 'self' data:; img-src 'self' data: blob:; connect-src 'self';
worker-src 'self' blob:; object-src 'none'; base-uri 'self'; frame-ancestors 'none'
```

- `style-src 'unsafe-inline'`：KaTeX 渲染会写内联 `style` 属性（必需）。
- `img-src data: blob:`：导出报告内嵌 PNG dataURL。
- 若将来重新引入 CDN 回退（离线不可用场景），需同步放宽 `script-src`/`font-src`/`style-src`。

## 4. CI 覆盖

`.github/workflows/ci.yml`

| job | 内容 |
|---|---|
| `verify` | v1：`node --check` + lint + 全部测试 + 构建校验 |
| `v2` | v2：`npm ci` → `check` → **`parity`（内核红线）** → `audit` → `uidata` → `perf` → `build` → 体积报告 → `dist/_headers` 存在性自检 |
| `deploy`（另一文件） | v2：构建 + 产物 self-check（相对 base）+ 按密钥有无决定是否发布 Pages |

## 5. 发布前检查清单

- [ ] `npm run check` 零错误
- [ ] `npm run parity` **77/77 对拍 + 37/37 闭式真值**
- [ ] `npm run audit` **9/9**；`npm run uidata` **90/90**
- [ ] `npm run perf` 全绿（主线程合计 ≤ 150 ms，单项 ≤ 25 ms）
- [ ] `npm run build` 通过，`dist/_headers` 与 `dist/index.html` 就位
- [ ] `dist/index.html` 引用形如 `./assets/…`（相对路径 → 任意子路径可部署）
- [ ] 首页首屏未请求 `katex-*.js`（KaTeX 按需）
- [ ] 手动走查：进入任一工具、公式渲染、结果条「图表 PNG / 导出报告 / 存 A / 存 B」、设置中心、学习路径、对比实验
      （走查基准见 `docs/v2/M17-走查报告.md`：21 个视图 · 零业务 console error）
